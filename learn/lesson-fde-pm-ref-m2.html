2.1 Core architectural concepts

Client-server, monolith, microservices, distributed systems

Shape Strength Cost the PM must price
Monolith Simple deploy, easy local reasoning Change collision; scaling one hot path scales all
Microservices Independent deploy, clear ownership *if* domains are bounded Network failure modes, ops overhead, distributed transactions
Distributed system Scale and isolation Partial failure is normal; you need SLOs, retries, idempotency

Fowler: monolith first is often rational; microservices are a *premium* you pay for independent teams/releases — not a virtue signal. Uber’s domain work: unbounded service graphs become unownable (Conway).

C4 model: Shared vocabulary for diagram altitude (context / container / component). Demand the right altitude in reviews.

Sync vs async

Style Examples PM implication
Synchronous REST request/response User waits; latency budget is the product; timeouts are UX
Async Webhooks, Kafka/RabbitMQ streams Eventual consistency; “done” means processed, not acknowledged
Broker patterns Routing, dead-letter, competing consumers (EIP) Failure handling is a product requirement — who retries, who alerts

Data persistence

Store Use when PM traps
SQL / relational Strong consistency, joins, auditability Schema evolution is a one-way door — own migrations in change control
NoSQL Flexible docs, horizontal scale patterns “Schemaless” still has an implicit schema; query patterns lock you in
Cache (Redis) Latency lever Stale reads are a product decision; TTLs are acceptance-relevant
Warehouse Analytics, not OLTP path Don’t put the assistant’s hot path on the warehouse

Kleppmann is the credibility book for data conversations with serious engineers.

AI overlay (folded M1–M3): Transformer shape / context budget; RAG as retrieve→condition→generate; agents as reason+act (prefer simple patterns); lost-in-the-middle is a product risk.

2.2 Reliability, networking & security

Performance vocabulary

  • Latency budget: End-to-end time the user/system may spend; allocate across retrieval, model, tools.
  • Throughput: Successful work per unit time.
  • Concurrency: Simultaneous in-flight work — saturates pools and rate limits.
  • Rate limiting: Protects you and the client; product must define UX when limited.
  • Tail latency: p99 hurts more than averages (Dean & Barroso). SLOs are negotiated budgets (Google SRE).

Security lexicon (decision altitude)

Term Meaning for the PM
CIA triad Confidentiality, Integrity, Availability — every design review maps here
RBAC / ABAC Role vs attribute entitlements; retrieval must respect the *requesting user*
OAuth 2.0 / OIDC Delegated auth / identity layer for modern APIs
SAML / SSO Enterprise identity federation — often a commit-blocker
VPC / peering Network boundaries; air-gap and private connectivity are one-way doors
Zero Trust (SP 800-207) Never trust network location alone — vocabulary security architects already use

Enterprise trust (folded M8): Map OWASP LLM Top 10 and NIST AI RMF (govern/map/measure/manage) to design decisions *before* review. Questionnaire answers come from architecture, not “ask eng later.”

2.3 Technical debt & engineering overhead

Technical debt (Fowler quadrant): not “engineers want to polish.” It is deferred cost with interest — reckless/prudent × deliberate/inadvertent.

Toil (SRE): manual, repetitive, automatable work that doesn’t create enduring value. High toil on an FDE team is a productization signal.

Negotiation Bad PM move Better
Refactor vs feature “No refactors until roadmap done” Price debt interest (slow delivery, incident rate); schedule paydown as capacity %
Platform vs bespoke Always say yes to client Three-way price: config / bespoke / product candidate
Utilization 100% billable Dual allocation: deploy / harvest / core
