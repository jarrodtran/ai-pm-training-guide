3.1 Role definition

Role Primary job Success Failure mode
FDE (Delta) Ship working systems in *client* context Time-to-first-deploy; trusted in the room Permanent heroics; unharvested forks
Core SWE (Dev) Build product/platform Reuse, SLOs, paved road Blind to field constraints
Solutions Architect Design fit (often pre-sales heavy) Credible design the team can build Paper architecture; no run ownership
Sales Engineer Prove feasibility to win Demo that closes Overpromise FDE inherits
You (PM of FDEs) Outcomes, constraints, acceptance, shield, harvest Measured outcomes + rising reuse PM-theater / project-only

Palantir day-in-the-life: time with users, in data, negotiating scope — which hours are *product* work, and who owns them? (Dev vs Delta: deployment context defines the role.)

Vendor platform vocabulary: Palantir Foundry docs show how a serious platform describes tenancy, access, deployment, and auditability to enterprise buyers — use as a quality bar for what your security questionnaire answers should eventually look like.

3.2 Dual mandate: field speed vs platform defensibility

Mandate Optimize for If ignored
Field speed Trust, time-to-value Body shop
Platform defensibility Reuse, config-over-fork, shared entities (ontology thesis) Margin and velocity collapse

Utilization as north star starves harvest. Publish deliberate allocation: deployed / harvesting / core.

Multi-environment (Baseline team): multi-cloud / on-prem / gov networks is a product cost with a team attached, not a sales checkbox.

S-1 risk framing (Palantir S-1 primary; bots may 403): bespoke work pressures margins — harvest is the structural antidote.

Paved road: Uber Michelangelo — platform as shared train/deploy/monitor path, not a library per engagement. Stripe API versioning: client interfaces are decade-scale promises.

3.3 Field → core feedback loop

Three-client rule: third same request = market signal; first two = learning.

  1. 1. Log in pattern ledger (variation axes, cost of bespoke)
  2. 2. Open productization memo (or honest-no with reasoning)
  3. 3. Define config axes + core interface; deprecate bespoke versions (the skipped step)
  4. 4. Design-partner framing: what client gets / keeps / must consent to

Team Topologies: engagement (stream) / platform / enabling — deliberate. Conway’s law: org shape becomes architecture. DORA: delivery performance vocabulary with eng leadership — not vanity dashboards.

3.4 Field realities & anti-patterns

Anti-pattern Looks like PM move
Scope creep Silent yeses Shield with price; SOW change control
Permanent forks Branch per client Config + extension points; kill long-lived forks
Dirty data surprise “Clean later” Data readiness gate before build
On-prem friction ignored Sales promised; no capacity Price multi-env explicitly
Agent theater Open autonomy for a form submit Prefer RAG + confirmed action
Eval after demo Taste-test acceptance Done-before-build
