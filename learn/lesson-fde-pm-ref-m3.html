3.1 Role definition

Role Primary job Success looks like Failure mode
FDE (Delta) Ship working systems in *client* context Time-to-first-deploy; trusted in the room Permanent heroics; unharvested forks
Core SWE (Dev) Build the product/platform Reuse, SLOs, paved road Blind to field constraints
Solutions Architect Design fit; often pre-sales heavy Credible design the team can build Paper architecture, no ownership of run
Sales Engineer Prove feasibility to win Demo that closes Overpromise that FDE inherits
You (PM of FDEs) Outcomes, constraints, acceptance, shield, harvest Measured outcomes + rising reuse PM-theater / project coordination only

3.2 Dual mandate: speed vs defensibility

FDE engagements produce high revenue/head and mediocre margin if everything stays bespoke. What compounds is the repeated pattern.

Mandate Optimize for Starve if ignored
Field speed Client trust, time-to-value Becomes a body shop
Platform defensibility Reuse, config-over-fork, ontology Margin and velocity collapse

Utilization is a trap as north star. Publish deliberate allocation: deployed work / harvesting / core building.

Multi-environment (Baseline team lesson): supporting many clouds/on-prem/gov networks is a product cost with a team attached — not a sales checkbox.

3.3 Field → core feedback loop

Three-client rule: Third same request = market signal; first two = learning.

Loop:

  1. Log pattern in pattern ledger (axes of variation, cost of bespoke).
  2. Open productization memo (or honest-no with reasoning).
  3. Define config axes + core interface; deprecate bespoke versions (the skipped step).
  4. Design partner framing: what client gets / keeps / must consent to.

Team topology: Engagement (stream) / platform / enabling — deliberate (Team Topologies). Conway’s law: org shape becomes architecture.

DORA metrics: vocabulary for delivery performance conversations with eng leadership — not a vanity dashboard.

3.4 Field realities & anti-patterns

Anti-pattern What it looks like PM move
Scope creep Silent yeses Shield with price; SOW change control
Permanent forks Branch per client Config + extension points; kill long-lived forks
Dirty data surprise “We’ll clean later” Data readiness gate before build (Gate 3)
On-prem friction ignored Sales promised; no Baseline-like capacity Price multi-env support explicitly
Agent theater Open autonomy for a form submit Prefer RAG + confirmed action (M3)
Eval after demo Taste test acceptance Done-before-build (M4)
